# Agent instructions

Briefing for coding agents working in this repo (Claude Code loads it through `CLAUDE.md`; Cursor and Codex read it directly).

This is the **Backstop** Scaffold-HBAR template: an RFQ desk on Hedera. A taker escrows a swap order. Market makers answer with EIP-712 signed quotes posted to a Hedera Consensus Service (HCS) topic. The best quote settles on chain through HTS allowances, inside a Chainlink sanity band. If nobody fills before the order expires, the order's own Hedera Schedule Service (HSS) call swaps the escrow on SaucerSwap V2 and pays the taker, so every order ends in tokens or a refund.

## Units: the most common source of bugs here

- **HBAR in the EVM is tinybar (8 decimals).** `msg.value`, `address(this).balance`, `fuelPerOrder` and `tx.gasprice` are tinybar. At the JSON-RPC layer wallets send 18-decimal weibar, so the frontend uses `parseEther("10")` for 10 HBAR and the contract sees `1_000_000_000`.
- WHBAR has 8 decimals; USDC and SAUCE have 6. `amountIn`, `minOut` and quote `amountOut` are raw units of their token. `hbarUsd()` is USD with 8 decimals; `usdDecimals` carries the stablecoin's.
- Quote JSON on HCS carries every integer as a decimal string so no consumer loses precision. The EIP-712 types are `Quote(uint256 orderId,address maker,uint256 amountOut,uint64 deadline,uint256 nonce)` under domain `{name "Backstop", version "1", chainId, verifyingContract}`.
- HTS amounts are `int64`; the desk only moves ERC-20 facades, so it never casts.

## Invariants: do not break these

1. **An order exists only with a booked fallback.** `postOrder` books `fallbackFill(id)` through HSS and reverts `ScheduleFailed` when the Schedule Service refuses. There is no open order without a schedule, which is what makes "every order fills" true.
2. **`fallbackFill` never reverts after its `OnlySelf` check.** A settled order is skipped (`FallbackSkipped`), a failed swap refunds the escrow (`Refunded`), a refund that cannot be paid parks the escrow as `claimable`. The swap runs in its own frame with all but `REFUND_RESERVE` gas and reads two return words at most, so a burning router or a revert payload bomb cannot stop the refund. Tests: `test_fallback_aRouterThatBurnsAllItsGasStillRefunds`, `test_fallback_reservesGasForAnExpensiveRefund`, `test_fallback_aRevertPayloadBombCannotStopTheRefund`.
3. **Escrow equals the open orders plus unclaimed refunds, per token, and the desk holds exactly that.** `escrowed[token]` moves on every post, fill, cancel, fallback and claim. `BackstopInvariant.t.sol` asserts it, and asserts native fuel equals open-order fuel plus the fuel fallbacks kept.
4. **A quote binds its order, maker, amount, deadline, nonce, chain and desk, and only the order's taker may submit it.** The digest includes `orderId`; the domain includes `chainId` and the desk address; the recovered signer must equal `quote.maker`. Quotes are public on the topic, so `fillWithQuote` is taker-only: a stranger cannot settle an order with the worst valid quote on the board. Nonces are a Permit2-style bitmap (`nonceBitmap[maker][nonce / 256]`, bit `nonce % 256`); a nonce is marked only by a successful fill, so a reverted fill (maker short of allowance) does not burn it, and `cancelNonces(wordPos, mask)` lets a maker withdraw up to 256 quotes in one transaction.
5. **The Chainlink band fails closed.** For WHBAR against the USD token, a quote below the oracle-implied amount less `maxDeviationBps` is rejected, and a stale or non-positive feed reverts the fill. Other pairs have only the order's `minOut`. The fallback never reads the oracle, so a dead feed blocks quotes but never an exit.
6. **The fallback swaps at the taker's own floor, straight to the taker.** `amountOutMinimum` is `minOut`, `minOut` is non-zero, and the router's recipient is the taker, so the desk never holds tokenOut.
7. **A fill or a cancel deletes the schedule and refunds the order's fuel; a fallback keeps the fuel.** The deletion response code is emitted (`ScheduleDeleted`) and never gates the settlement. A fuel refund that a contract taker rejects emits `FuelRefundFailed` on a fill and reverts on a cancel.
8. **One `scheduleCall` per transaction.** `postOrder` and `rearm` each book exactly once. Nothing in the scheduled path books.
9. **Quotes close at `expiry`; the fallback checks no time.** Scheduled calls read a clock about two seconds early, so a deadline check inside `fallbackFill` would reject the network's own run.
10. **`rearm` is the only repair for a schedule that did not settle its order**, allowed `RETRY_GRACE` seconds after expiry and `MAX_REARMS` times per order. A stale schedule that still runs finds the order settled and skips it.
11. **No owner, no admin, no fee.** Nothing can move escrow except the paths above. Fuel left by fallbacks stays in the desk and pays for later runs.
12. **Escrow is measured, never assumed.** `postOrder` refuses a tokenIn or tokenOut whose HTS custom fee schedule (`getTokenCustomFees`) is not empty, requires the balance delta of the intake to equal `amountIn`, and every payout of tokenIn re-checks that the desk still holds what it owes (`Insolvent`). WHBAR (0.0.15058), USDC (0.0.5449) and SAUCE (0.0.1183558) have empty schedules and no fee schedule key, so their fees cannot change.
13. **The constructor rejects what it cannot trust:** zero addresses, `scheduledGas` under 3,000,000, zero fuel, a band of 0 or 10,000 bps or more, zero oracle age, a feed that is not 8 decimals, stablecoin decimals above 18. `usdDecimals` is passed in because an HTS token cannot be called from a forge script simulation.

## Hedera behaviour the code depends on

| Behaviour | Where it matters |
| --- | --- |
| A scheduled call runs with `msg.sender` = the contract that booked it | `fallbackFill` and `swapEscrow` use it as their only access check (`OnlySelf`) |
| The scheduled transaction is paid by the booking contract, not the user | Measured 0.7282 HBAR for one fallback (swap included) against a 3,000,000 gas booking; `fuelPerOrder` (4 HBAR) must cover the gas reservation (`scheduledGas` x gas price, about 2.64 HBAR at 88 tinybar per gas) |
| A scheduled execution of a contract-created schedule shows `scheduled: true` on the mirror node, payer = the contract | The evidence check reads it from `/transactions?account.id=<desk>` |
| `scheduleCall` costs about 1.4M gas; a scheduled call under 3M gas is not reliable | `MIN_SCHEDULED_GAS = 3_000_000`; `postOrder` is sent with 5M gas, measured 1.70M used |
| Expiry more than 62 days out is refused | `MAX_TTL = 60 days` |
| A busy second refuses new schedules (`SCHEDULE_EXPIRY_IS_BUSY`) | `_secondWithCapacity` probes +1, +2, +4 ... +64 s; if every probe is full `postOrder` reverts and the taker retries |
| Scheduled calls read a clock about two seconds early | No time check in `fallbackFill`; the schedule books `expiry` itself |
| An account must be associated with an HTS token to receive it | The desk self-associates tokenIn through HIP-719 (`associateTokens`, or lazily in `postOrder`); contracts get no automatic associations. EOAs auto-created by a transfer have unlimited ones, so a maker needs no association step |
| An HTS token can carry fixed, fractional or royalty custom fees that change what a transfer moves | `postOrder` reads `getTokenCustomFees` (precompile 0x167) for both tokens and refuses any fee; the live testnet tokens return empty schedules and have no fee schedule key |
| A refund to a taker not associated with tokenIn cannot be paid | `fallbackFill` parks it as `claimable`; `claim(id)` pays once the taker associates |
| An HTS approval from a contract costs about 700k gas and HTS refuses one above max supply | `swapEscrow` approves the router for `totalSupply()` once per token |
| A contract pulling an approved HTS token with `transferFrom` is cheap | Measured 43,536 gas for a whole transaction doing one pull; the maker approves the desk once (about 727k gas) |
| `ecrecover` and EIP-712 digests behave as on Ethereum, with `block.chainid` = 296 | Measured on testnet: a viem `signTypedData` quote recovers to the maker on chain and the digest equals viem's `hashTypedData`; `test_signature_viemVectorRecovers` pins the same vector |
| HCS: a topic without a submit key accepts messages from anyone, up to 1024 bytes, ordered by network-assigned consensus timestamp | HCS is a public quote board with network-assigned timestamps, not an ordering guarantee: anyone can post junk, so readers verify the signature and the order id before showing a quote, and settlement rests on the maker-signed price, the deadline and the order's expiry, never on receive order |
| HCS messages reach the mirror node a few seconds after consensus (about 7 s submit to visible in the live run) | The app polls `/api/v1/topics/{id}/messages`; a quote is shown only after it is readable |
| The Chainlink HBAR/USD heartbeat is 24 hours and testnet pools are not arbitraged (pool near $1.8, feed near $0.10) | `maxOracleAge` is 90,000 s; on testnet the band admits any quote at or above the pool because the pool is richer than the feed |
| `eth_getLogs` on Hashio is range-limited | The UI and the maker read events from the mirror node `/contracts/{id}/results/logs` |
| A forge script simulation cannot call an HTS token facade | The constructor never calls a token; `usdDecimals` is a parameter |
| Foundry 1.8 is rejected by Hashio (relay#5826) | Use `foundryup --install v1.7.1` for scripts against testnet |

`scripts/verify-evidence.sh` re-reads the canonical testnet run (orders, topic message, scheduled transaction, Sourcify match) from chain.

## Common changes

- **Add a pair:** any SaucerSwap V2 pair the factory knows works as is, with `minOut` as the floor. To put another pair under the Chainlink band, extend `_oracleFloor` with its feed.
- **Change the fuel:** `FUEL_PER_ORDER` in `Deploy.s.sol` (tinybar). Keep it above `scheduledGas` x the network gas price.
- **Mainnet:** swap the addresses in `Deploy.s.sol` for the mainnet ones (SaucerSwap docs, Chainlink feed directory) and chain id 295 in the maker and the app.
- **New contract behaviour:** add the test first in the matching `test/Backstop*.t.sol`, then change the contract. Mocks are in `test/mocks/`; extend them rather than calling a live network from unit tests.
- **Check that a test can fail:** break the guard it covers, confirm red, restore, confirm green.

## Frontend conventions

- Scaffold hooks: `useScaffoldReadContract`, `useScaffoldWriteContract`, `useScaffoldEventHistory`, `useDeployedContractInfo`, `useTransactor` (in `hooks/scaffold-hbar`).
- `~~` import alias, `"use client"` on pages that use hooks, DaisyUI classes, `type` over `interface`.
- Every number on screen comes from the chain or the mirror node. No hard-coded prices or balances.
- Verify a quote client-side with viem `verifyTypedData` before showing it as fillable.

## Before you call something done

`yarn foundry:test`, `yarn lint`, `yarn next:check-types`, `yarn next:build` all pass. For contract changes, also run `yarn foundry:live` and check the HashScan links it prints. A transaction hash proves the network accepted a call; the order's status afterwards (`getOrder(id).status`), the taker's token balance and the mirror's `scheduled: true` row prove it did what you meant.
