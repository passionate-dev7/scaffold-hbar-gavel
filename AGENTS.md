# Agent instructions

Briefing for coding agents working in this repo (Claude Code loads it through `CLAUDE.md`; Cursor and Codex read it directly).

This is the **Index Basket** Scaffold-HBAR template: a tokenised index fund on Hedera. `BasketVault` takes HBAR, buys a weighted basket of HTS tokens on SaucerSwap V2, mints an HTS share token, pays redemptions out in kind, and books its own rebalances through the Hedera Schedule Service. Chainlink HBAR/USD prices the fund in USD.

## Units: the most common source of bugs here

- **HBAR in the EVM is tinybar (8 decimals).** `msg.value`, `address(this).balance` and `tx.gasprice` are tinybar. At the JSON-RPC layer wallets send 18-decimal weibar, so the frontend uses `parseEther("10")` for 10 HBAR and the contract sees `1_000_000_000`.
- WHBAR and the share token have 8 decimals; SAUCE and USDC have 6. `nav()` is WHBAR tinybar. `navUsd()`, `sharePriceUsd()` and `hbarUsd()` are USD with 8 decimals.
- HTS amounts are `int64`. The vault converts with `SafeCast`; never with a bare cast.

## Invariants: do not break these

1. **Redeem never reads a price.** It pays each token pro rata from balances. A stale oracle or a broken pool must never trap a holder. A test proves redeem succeeds while deposit reverts on a stale feed.
2. **Deposits are valued at pre-trade spot prices.** The depositor's own price impact and pool fees reduce their shares, not existing holders' value.
3. **The first deposit locks `DEAD_SHARES` in the treasury** (share-inflation defence). Do not remove it.
4. **`runScheduled` never reverts and books its successor before rebalancing.** It is the only way the automation chain continues. A failed rebalance costs one run; a revert would cost the chain.
5. **One `scheduleCall` per transaction.** A second booking in a scheduled execution fails the whole transaction (`NO_SCHEDULING_ALLOWED_AFTER_SCHEDULED_RECURSION`).
6. **Native HBAR in the vault is fuel, never basket value.** The HBAR leg is held as WHBAR. `withdrawFuel` can only move native HBAR.
7. **`rebalance()` is owner-or-vault only (`OnlyOwnerOrSelf`).** Its sizing and slippage floor come from pool spot prices, so a permissionless caller could move a pool earlier in the same transaction, let the vault trade against it and trade back. `test_regression_outsiderCannotProfitFromRebalance` shows 524 HBAR of attacker profit on a 200,000 HBAR vault without the gate and every sandwich reverting with it. Never open the gate.
8. **A lost booking keeps `rebalanceInterval`.** `runScheduled` emits `BookingFailed` and leaves automation on; `rearm()` is permissionless and books the next run when none is pending.
9. **`redeemExcept(shares, skipLegsMask)` is the exit for a frozen or paused leg.** `redeem(shares)` is `redeemExcept(shares, 0)`; the skipped slice stays in the vault for the remaining holders. Neither reads a price.
10. **The constructor rejects what it cannot trust:** a pool that is not the SaucerSwap V2 factory's pool for the pair and fee, duplicate leg tokens, zero slippage, zero oracle age, a guard with zero tolerance, a feed that is not 8 decimals. Each rebalance swap moves at most `maxTradeBps` of NAV (2000 on the deployed vault).
11. **`stopAutomation` emits `ScheduleDeleted(schedule, responseCode)`** with the Schedule Service's answer.

## Hedera behaviour the code depends on

| Behaviour | Where it matters |
| --- | --- |
| A scheduled call runs with `msg.sender` = the contract that booked it | `runScheduled` uses it as its only access check (`OnlySelf`) |
| `scheduleCall` alone costs about 1.4M gas; a self-rescheduling call under 3M gas runs once and silently fails to book its successor | `MIN_SCHEDULED_GAS = 3_000_000`; deploy uses 4M |
| Expiry more than 62 days out is refused | `MAX_INTERVAL = 60 days` |
| A busy second refuses new schedules (`SCHEDULE_EXPIRY_IS_BUSY`) | The booking second is interval + 0 to 29 s of jitter; `_secondWithCapacity` probes +1, +2, +4, +8, +16, +32, +64 s |
| A HTS issuer can freeze or pause a basket token | `redeemExcept` skips that leg |
| A refused booking inside a run must not end the chain | `BookingFailed` is emitted, the interval is kept, `rearm()` books later |
| The payer must hold the full gas reservation (`scheduledGas` x gas price), not just what a run burns | Keep fuel above that or bookings fail; the UI shows runs remaining |
| HTS refuses an allowance above a finite token's max supply, and an approval from a contract costs about 700k gas | `_swap` approves `totalSupply()` once and re-approves only when short |
| An account must be associated with an HTS token before it can receive it | Vault self-associates in `initialize`; users associate the share token before depositing and the basket tokens before redeeming |
| Testnet pools are not arbitraged: the WHBAR/USDC pool can sit far from Chainlink | The pool-vs-Chainlink guard is off in the testnet deploy (`guardLeg = type(uint256).max`); turn it on for mainnet |
| `eth_getLogs` on Hashio is range-limited | The UI reads events from the mirror node `/contracts/{id}/results/logs` |

## Common changes

- **Change the basket:** edit `legs` in `script/Deploy.s.sol`. Every leg needs the SaucerSwap V2 factory's own pool paired with WHBAR (the factory address in `Deploy.s.sol` is 0.0.1197038, `0x...1243eE`); the constructor rejects anything else. Weights are basis points; WHBAR gets `10_000 - sum(legs)`.
- **Turn on the price guard:** set `guardLeg` to the index of a USD stablecoin leg and `maxDeviationBps` to the tolerance (for example 300).
- **Mainnet:** swap the addresses in `Deploy.s.sol` for the mainnet ones (SaucerSwap docs, Chainlink feed directory) and enable the guard.
- **New contract behaviour:** add the test first in the matching `test/BasketVault*.t.sol`, then change the contract. Mocks are in `test/mocks/`; extend them rather than calling a live network from unit tests.

## Frontend conventions

- Scaffold hooks: `useScaffoldReadContract`, `useScaffoldWriteContract`, `useScaffoldEventHistory`, `useDeployedContractInfo`, `useTransactor` (in `hooks/scaffold-hbar`).
- `~~` import alias, `"use client"` on pages that use hooks, DaisyUI classes, `type` over `interface`.
- Every number on screen comes from the chain or the mirror node. No hard-coded prices or balances.

## Before you call something done

`yarn foundry:test`, `yarn lint`, `yarn next:check-types`, `yarn next:build` all pass. For contract changes, also run `yarn foundry:live` and check the HashScan links it prints. The canonical deployment is vault C (`0xe72FbF68536D29d3A9e0D897C2aE813B7B279058`, share token 0.0.10839906); evidence is in `docs/testnet-evidence.md`. A transaction hash proves the network accepted a call; the vault's state afterwards (`holdings()`, share balance, `nextRunAt`) proves it did what you meant.
